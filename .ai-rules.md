# ИНСТРУКЦИЯ ПО РАЗРАБОТКЕ CAD-РЕДАКТОРА ДЛЯ ИИ (KILO VS CODE)

## КРИТИЧЕСКОЕ ПРАВИЛО: ЗАПРЕТ НА DOM API

1. Вам КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО использовать любые методы DOM API (`document`, `window`, `querySelector`, `createElement`, `SVGElement`, `HTMLElement` и т.д.) во всех файлах, кроме `Renderer.ts`.
2. В проекте работает жесткий кастомный линтер `anti-dom/no-dom-api`. Любая попытка вызвать DOM API вызовет ошибку компиляции.
3. Вся работа с элементами, хит-тестами и математикой должна происходить В ПАМЯТИ на уровне чистых TypeScript-классов и массивов.

## АРХИТЕКТУРА ЭЛЕМЕНТОВ (КОМПОЗИЦИЯ)

Все SVG-элементы наследуются от базового класса `SvgElement` и используют строгую композицию внутренних модулей. Запрещено раздувать классы элементов чужой логикой.

### 1. Зоны ответственности SvgElement (Базовый класс):

- **Жизненный цикл кадра:** Управление флагами изменений (`dirty`, `setDirty()`, `markClean()`), клонирование (`clone()`).
- **Единая точка мутации:** Любое изменение положения, размера или угла ОБЯЗАНО проходить строго через метод `applyTransformation()`.
- **Математика координат:** Перевод локальных координат в мировые (`transformPoint()`, `getLocalCenter()`, `getTransformedBBox()`, `getCenter()`).
- **Движок трансформаций:** Чистые методы `translate()`, `applyDelta()`, `rotate()`.
- **Шлюз состояния:** Изменение стилей (`setFill()`, `setStroke()`, `setStrokeWidth()`, `setOpacity()`, `setVisible()`). Каждый вызов взводит флаг `dirty` и ставит элемент в очередь на рендеринг.
- **Сериализация:** Экспорт/импорт данных (`toJSON()`, `toDTO()`, `applyDTO()`).
- **Чистые геттеры:** Быстрый доступ к `x`, `y`, `scaleX`, `scaleY`, `angle`.

### 2. Рендеринг через Snapshot (Потоковая отрисовка)

Связующим звеном между элементом и графическим движком является Единственный Публичный Метод: `getRenderSnapshot()`.

- Метод возвращает плоский объект (DTO) со свойствами: `id`, `type`, `matrix` (массив чисел), `style` (без vector-effect), и `geometry` (специфичные свойства).
- Конкретные элементы (например, `SvgPath`) переопределяют ТОЛЬКО метод `getGeometryProps()`, возвращая свои уникальные атрибуты (например, `dAttribute`).
- **Запрещено:** Писать код отрисовки или обновления DOM внутри элементов. Это делает только `Renderer.ts`, читая snapshot.

### 3. Ленивая HitArea (Массив точек)

- Модуль `HitArea` отвечает ТОЛЬКО за создание, кеширование и обновление локального массива точек контура фигуры (`Point[]`).
- Все точки генерируются строго в локальной системе координат элемента (без учёта трансформации).
- При вызове `applyTransformation()` кеш точек обязан сбрасываться через `invalidateHitArea()`.
- Фигуры (Rect, Circle, Polyline, Path) аппроксимируют свои контуры в плоский массив точек по строгим математическим формулам (через sin/cos, нормали сегментов, miter join, butt caps, flattenCommands) БЕЗ использования контекста канваса или DOM.

## РЕЖИМ РАБОТЫ ДЛЯ ИИ

1. Пишите код строго АТОМАРНО. Один запрос — один метод или одно свойство.
2. Не пытайтесь "помочь" архитектуре, вызывая скрытые методы или создавая DOM-обертки.
3. Если вам нужно изменить поведение элемента — меняйте данные в его модуле (`Transform`, `Style`, `HitArea`), а не пишите обходные пути.
